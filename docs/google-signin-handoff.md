### Option A — Firebase Console (fastest, 30 seconds)

1. Open your Firebase project → **Authentication** → **Sign-in method**.
2. Click **Google** in the provider list.
3. Expand **Web SDK configuration**.
4. Copy the **Web client ID** — it looks like:
   `195179237561-jce7rmr4ou8jf2lsvt8lthv0q5h52o5a.apps.googleusercontent.com`
5. Paste it into the reply.

### Option B — Google Cloud Console

1. Same Google Cloud project as Firebase → **APIs & Services** →
   **Credentials**.
2. Under **OAuth 2.0 Client IDs**, find the entry of type
   **Web application** (there's usually one auto-generated by Firebase,
   often named "Web client (auto created by Google Service)").
3. Copy the **Client ID** column value.

Only the **Web** client ID matters — please don't send the Android or
iOS ones, those don't work as an audience.

## Why "Web" and not Android/iOS?

Our backend verifies the Google ID token by checking its `aud`
(audience) claim against a single value. Both native apps use the
same Web client ID as their `serverClientID` when calling `GIDSignIn`
/ `GoogleSignIn`, so the token comes back with the Web client ID as
the audience — which is what the backend verifies.

This is exactly how the Firebase Auth SDK does it internally, so
switching from Firebase Auth to raw Google Sign-In changes nothing
about which value is needed.
